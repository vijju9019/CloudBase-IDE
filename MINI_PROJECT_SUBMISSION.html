3. Abstract (Guideline 3: Problem statement and process of mini project conduction)

Modern software development relies heavily on either cloud-hosted web IDEs (such as GitHub Codespaces and Replit) or traditional desktop editors (such as VS Code). While cloud IDEs enable universal browser accessibility, they introduce critical vulnerabilities: recurring subscription expenses, unpredictable network latency, vendor lock-in, and the exposure of proprietary intellectual property and source code to remote third-party cloud servers. Conversely, traditional desktop editors execute with uncontained host-level operating system privileges, leading to host environment pollution across conflicting runtime versions and leaving host workstations exposed to malicious dependency scripts (e.g., typosquatting or arbitrary execution via untrusted npm/pip packages).

CloudBase IDE resolves this fundamental architectural dilemma by engineering an enterprise-grade, local-first, browser-accessible integrated development environment that guarantees absolute privacy, hardware-enforced container isolation, and zero-compromise developer ergonomics. The system integrates: (1) a VS Code-inspired React 18 single-page application incorporating Monaco Editor (v0.52) and an interactive xterm.js canvas terminal communicating over low-latency full-duplex WebSockets; (2) Storage Guardian, a defense-in-depth security subsystem enforcing strict canonical path jailing within %LOCALAPPDATA%\CloudBaseIDE\Projects, mitigating Zip-Slip vulnerabilities and rejecting host directory escapes; (3) a hardware-isolated container execution runtime managed via Dockerode on WSL2, providing instantly provisioned micro-containers for Python 3.12, Node.js 22, React SPA, Java 21, C++ (GCC 13), and Go 1.22 with strict CPU and RAM ceilings; (4) an on-device, 100% offline neural coding assistant leveraging local Qwen2.5-Coder weights via Ollama with typewriter streaming and side-by-side Monaco diff inspection; and (5) a native persistence layer powered by Node.js 24's zero-dependency node:sqlite engine running in Write-Ahead Logging (WAL) mode.

The process of mini project conduction adheres to a systematic six-phase Agile-Iterative engineering lifecycle: Phase 1: Literature survey, threat modeling against path traversal, and SRS formalization; Phase 2: Multi-tier architecture design and security perimeter specification; Phase 3: Frontend workspace development with Monaco Editor and Storage Guardian canonical path validation; Phase 4: Docker container lifecycle orchestration and WebSocket terminal multiplexing; Phase 5: Offline LLM token streaming integration, visual diff review modal, and native SQLite schema migrations; and Phase 6: Automated security validation (Vitest test suite), PowerShell diagnostic health checks, and academic documentation. Benchmarking verifies sub-50ms editor responsiveness, sub-10ms terminal input/output latency, 100% path traversal immunity, and complete offline autonomy with zero telemetry.

4. Problem Statement & Project Objectives
Problem Statement: Existing cloud-based IDEs compromise developer privacy, mandate continuous high-bandwidth internet connectivity, and incur recurring compute costs, whereas traditional desktop environments run unsandboxed with full host privileges, creating severe dependency conflicts and system vulnerability risks from third-party scripts.
Measurable Project Objectives:
  • Construct a high-performance web IDE with Monaco Editor, breadcrumbs, multi-tab editing, and status monitoring.
  • Implement Storage Guardian to mathematically eliminate directory traversal (../), symlink escapes, and host drive attacks.
  • Deploy hardware-level containerization for multi-language runtimes (Python, Node.js, React, Java, C++, Go) with resource limits.
  • Build an interactive full-duplex terminal using xterm.js and Socket.IO with character echo and Ctrl+C signal termination.
  • Integrate on-device neural AI using Ollama for typewriter code generation, diff review, and heuristic offline fallbacks.
  • Persist project metadata and audit logs using Node.js 24 native node:sqlite in WAL mode with zero compilation hurdles.
